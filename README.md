# Cross-Lingual Deep Unlearning — Large Public Data Study

Reproducible Kaggle notebooks investigating whether English-only machine unlearning transfers to German direct retrieval and multi-hop reconstruction (2–4 hops).

> **Current large configuration is not yet GPU-trained.** The earlier 72-case MQuAKE-T pilot completed, but results from it must not be represented as the large experiment. The new study expands to BOTH original-fact MQuAKE-T and MQuAKE-CF records, excludes ALL counterfactual edit targets, and uses original questions/answers. Only German translations are newly generated. Original MQuAKE-CF questions were generated by the benchmark authors, so these are publicly released QA, not independently human-written questions.

## Public source and scale

Source: [Princeton NLP MQuAKE](https://github.com/princeton-nlp/MQuAKE), the original (pre-edit) Wikidata fact chains in `MQuAKE-T.json` and `MQuAKE-CF.json`.

CPU-validated against downloaded official releases:

| Measure | Count |
|---|---:|
| Original public MQuAKE-T rows | 1,868 |
| Original public MQuAKE-CF rows | 9,218 |
| Combined raw public rows | 11,086 |
| Source-grounded, unique selected chains | 3,072 |
| Forget | 512 |
| Retain | 2,048 |
| Out-of-training holdout | 512 |
| 2-hop / 3-hop / 4-hop | 1,802 / 843 / 427 |

No counterfactual `new_answer`, `new_single_hops` or `new_triples` are incorporated into supervised labels. The 3,072-case sample is capped initially to respect your available Kaggle GPU hours, not because the underlying public dataset has only that many examples. Raise `N_FORGET`, `N_RETAIN`, and `N_HOLDOUT` in Notebook 01 to scale further, and monitor GPU time before doing so.

Independent utility benchmark: [HotpotQA](https://huggingface.co/datasets/hotpotqa/hotpot_qa), a ~113K human-written Wikipedia QA corpus. Notebook 03 samples a deterministic subset of the 7,405 annotated distractor-validation questions for **closed-book general-utility evaluation**, not as a substitute for matched single-hop unlearning evidence. The sample cap is configurable via `HOTPOT_UTILITY_N`. HotpotQA is CC BY-SA 4.0.

**Critical methodological caveat:** This remains an adaptation of knowledge-editing QA to unlearning, not a standard certified deletion benchmark. The pretrained 7B base can know original facts before SFT. A correct multi-hop final answer is not necessarily recovered first-hop secret knowledge.

## Research question

When a model is trained to forget direct English access to a target fact, does it still recover downstream answers via German 2–4-hop reasoning?

Note: recovering a downstream answer does **not** necessarily establish that the forgotten first-hop fact remains memorized. Full-SFT competence, baseline multilingual reasoning accuracy, retain utility, and retrained retain-only reference need to be checked before claiming a gap.

## Kaggle

Use GitHub Actions → **Kaggle notebooks** (manual workflow). It supports uploading all three **private** notebooks without running them, and optionally launching one stage at a time if explicitly requested. Runs consume your personal Kaggle GPU allocation, not GitHub-hosted GPU.

Set these repository **Settings → Secrets and variables → Actions** secrets:

- `KAGGLE_USERNAME`: your Kaggle account handle.
- **Recommended** `KAGGLE_API_TOKEN`: the value from **Generate New Token** at [Kaggle API settings](https://www.kaggle.com/settings/api).
- **Legacy alternative only:** `KAGGLE_KEY`, containing the `key` from a **legacy** `kaggle.json` file, paired with `KAGGLE_USERNAME`.

Modern API tokens (typically prefixed `KGAT_`) **must not** go in `KAGGLE_KEY`. You do not need to create both token types. The workflow checks credential presence and calls `kaggle quota` to verify authentication before publishing. Do not share tokens or commit credentials.

For the first workflow run, choose **stage = all**, **execute = false**. This creates three private notebook versions without running their cells.

For a real **large-dataset** run (do not reuse the pilot outputs, which have schema version 2):
- Run updated stage 01 with the larger configuration, wait for saved outputs and evaluate 64 randomly selected cases per train split.
- Configure stage 02 to include stage 01 as a Kaggle kernel input; run stage 02.
- Configure stage 03 to include both prior kernel outputs; run stage 03.

Generated LoRA checkpoints and data are Kaggle output artifacts, not tracked in Git. Complete artifact retrieval and inter-stage handoff should be verified on Kaggle before trusting the pipeline end-to-end.

## Research safeguards

- No generated factual relationships, answers, or fallback benchmark examples.
- The exact first-hop and multi-hop question/answer pairs come from the original dataset.
- German translations must be inspected for meaning and named-entity stability.
- Two-hop *forget* questions are excluded from SFT supervision.
- Never select checkpoints by looking at German test leakage.
- Hold-out methods, multiple seeds, temporal ambiguity checks and matched paired confidence intervals are still needed.
